mutastic prints its result on stdout and its progress on stderr. How the result looks is `--format`'s choice.

## Formats

`--format` chooses how much each missed mutant says, and for whom:

| Format | For | Each missed mutant |
|---|---|---|
| `full` | People at a terminal, the default there | A card: the gap, the code with the change marked, the evidence, the test to add, and how to prove it |
| `brief` | People who know the cards | The gap, the changed line and the evidence |
| `concise` | Logs and CI, the default off a terminal | One line |
| `grouped` | Reading many misses at once | One line, under its file and method |
| `agent` | Coding agents, the default with `MUTASTIC_AGENT=1` | Plain text: the verdict first, then the change, the fix and how to prove it |
| `jsonl` | Tools and scripts | One JSON event per line, as each mutant finishes |

- **Cards** are grouped by file, and in each file the method with the most misses comes first. A file shows at most seven cards, and counts the rest (`--each-mutant` shows them all): more than a few at once go unread. On a terminal, file locations are links (`--hyperlinks`) that terminals supporting OSC 8 open; others show the text.
- **The agent format's ten entries** are those most worth a test first: a condition or a removal no test checks before arithmetic, and among those, code more tests run without checking (a hypothesis, not yet measured). [`mutastic next`](/concepts/next/) hands them over one at a time, in the same order.
- **The agent format** puts the verdict first, so a truncated read still has it, and the rule that a fix changes tests, never production code. It also says when not to write one: a mutant whose case can't happen in practice, or whose change no caller can see, is declined with its reason and proposed for a person to ignore, not given a contrived test.
- **`MUTASTIC_FORMAT`** sets the format when `--format` isn't given. While it runs, each source file gets a line as it finishes, on stderr, with its misses under it.
- **`--vocabulary=classic`** (or `MUTASTIC_VOCABULARY=classic`) says killed and survived instead of caught and missed. JSON and the report files always use the standard statuses.
- **Colour** follows the usual rules: only on a terminal, never with `NO_COLOR` or `TERM=dumb`, always with `FORCE_COLOR`. Every colour has a symbol beside it (✓ caught, ✗ missed, ○ not covered, ⏱ timed out), so nothing is lost without it. Labels such as `MISSED` and `PASS` are coloured blocks, `[MISSED]` without colour, and have rounded ends with `MUTASTIC_PILLS=rounded` for terminals with a Nerd Font. `MUTASTIC_PILLS=off` draws no blocks: the label's words in its colour.
- **`jsonl`** writes `mutastic.events/v1` events, described field by field by [their JSON
  Schema](https://docs.mutastic.io/schemas/events/v1.json). Within v1 they only gain fields, events
  and values, never lose or rename one: see [Schemas and stability](/reference/schemas/). Statuses
  follow the mutation-testing report schema: `Killed`, `Survived`, `Timeout`, `NoCoverage`,
  `Ignored`. A few fields have better names beside the old ones, which go in 1.0.0: `rule` for
  `rules`, `caughtBy` and `caughtWith` for `killedBy` and `killedWith`, `killed` and the other
  counts for `Killed` and the rest, and `scope.fileCount` and `scope.lineCount` for `scope.files`
  and `scope.lines`. See [Deprecated names](/reference/schemas/#deprecated-names).
- **A mutant's id** comes from its class, method, position and change, not its line number, so it stays the same while code around it moves.

## Shared cards

The mutants of one line share a card, and an entry in the agent format: one test there usually
catches them all, the edge of a condition its boundary and its removal alike. The card is written
about one of them, with its id after the headline, and lists each of the others under `also`, with
its id and the line as it changes. A suggested test says which mutant it was found for. The card's
`done when` checks them all at once, so the test proves the whole fix; each is still counted, and
ignored, on its own.

## Streams

The result goes to stdout and progress to stderr, so `mutastic run > result.txt` keeps only the result.

## The commands it offers

The commands mutastic prints for a mutant name the project it ran on (`mutastic verify m855c8e3c samples/pricing`), so they work as copied. A mutant's id belongs to its project: run in a directory with no Java code, or one that isn't a Gradle or Maven build, mutastic says so (for Gradle, it names the modules that have Java code). A Maven module is named by its directory, as `-pl` takes it: `mutastic run . :services/api`.

## One mutant, explained

`mutastic explain ID [dir] [:module]` runs that one mutant and shows its card, whatever became of
it, then what it is. The summary's `Next:` line offers it, for the one-line formats. On the pricing

Under **About this mutant**:

- **bytecode**: the change, opcode by opcode (`IF_ICMPLT → IF_ICMPLE`), and how the jump relates to
  the source. javac compiles `if (total >= 100)` to a jump taken when `total < 100`, the opposite
  of what the source says, which is why a boundary mutant can look backwards in the bytecode.
- **operator**: what its operator does, as on [Operators](/concepts/operators/).
- **id**: how the id is made, and why it stays the same when code above it moves.
- **site**: which of the method's sites it is.
- **last run**: how the last full run went, or `none yet`.

---
title: Operators
description: The kinds of change mutastic makes to your code, and the gap in the tests each one finds.
---

An operator is a kind of change. Each mutant is one operator applied at one place in your code.
Reports and rules name an operator by its id, `mutastic/boundary` say; each has its own anchor on
this page.

For why each one is worth catching, the bugs it stands for and the test that catches it, see
[Operators (advanced)](/concepts/operators-advanced/).

| Operator | Changes | Set |
|---|---|---|
| [`mutastic/boundary`](#boundary) | `<` and `<=`, `>` and `>=` | defaults |
| [`mutastic/comparison`](#comparison) | a comparison to the one that differs on one side: `<` to `!=` | stronger |
| [`mutastic/other-comparison`](#other-comparison) | a comparison to the others, and a condition to its opposite | stronger |
| [`mutastic/remove-conditional`](#remove-conditional) | a condition to always true, or always false | defaults |
| [`mutastic/logical-connector`](#logical-connector) | `&&` and `\|\|` | defaults |
| [`mutastic/math`](#math) | `+` and `-`, `*` and `/` | defaults |
| [`mutastic/arithmetic-replacement`](#arithmetic-replacement) | `+` to `*` | stronger |
| [`mutastic/return-value`](#return-value) | a returned value to the other `boolean`, `0`, an empty one or `null` | defaults |
| [`mutastic/remove-void-call`](#remove-void-call) | a call that returns nothing, removed | defaults |
| [`mutastic/remove-discarded-call`](#remove-discarded-call) | a call whose result is thrown away, removed | defaults |
| [`mutastic/remove-assignment`](#remove-assignment) | an assignment to a variable that already has a value, removed | defaults |
| [`mutastic/remove-field-write`](#remove-field-write) | a write to a field, removed | stronger |
| [`stream/remove-stage`](#stream-stage-removal) | a stream stage, removed | defaults |
| [`stream/swap-match`](#stream-match-swap) | `anyMatch`, `allMatch` and `noneMatch`, swapped | defaults |
| [`library/swap-string`](#string-method-swap) | a `String` method and the similar one: `startsWith` and `endsWith`, `toUpperCase` and `toLowerCase` | stronger |
| [`library/swap-index-of`](#indexof-swap) | `indexOf` and `lastIndexOf` | stronger |
| [`library/swap-math`](#math-method-swap) | `Math.min` and `Math.max`, `Math.floor` and `Math.ceil` | stronger |

A run uses the `defaults` set unless you [choose otherwise](#choosing-operators). Plugins can add
operators of their own: see [Plugins](/guides/plugins/).

## Boundary

`mutastic/boundary`. `<` becomes `<=` and the other way round: the off-by-one at the edge of a
range, which tests that only check values far from the edge never notice.

```java
if (total >= 100)   // becomes: if (total > 100)
```

## Comparison

`mutastic/comparison`, in the `stronger` set. A comparison becomes the one that gives the same
answer at its edge and on one side of it, and the other answer on the other side:

| Written | Becomes | Differs where |
|---|---|---|
| `a < b` | `a != b` | `a > b` |
| `a <= b` | `a == b` | `a < b` |
| `a > b` | `a != b` | `a < b` |
| `a >= b` | `a == b` | `a > b` |
| `a == b` | `a <= b`, and `a >= b` | `a < b`, and `a > b` |
| `a != b` | `a < b`, and `a > b` | `a > b`, and `a < b` |

It goes unnoticed when no test looks at that side, and the card names it: "no test checks
`shipping()` with `total > freeShippingFrom`".

With [boundary](#boundary) and [remove conditional](#remove-conditional), these make the smallest
set of changes that is enough for a comparison: tests that catch the edge moved, the side changed
and the condition always true or false catch every other way the comparison could be written
wrong. For `a < b` the three are `a <= b`, `a != b` and `false`. Each is one operator's, so no
condition gets the same change twice. Nor does a size: for a value that's never negative,
`items.size() > 0` becoming `items.size() >= 0` is the condition always true, so it's left to
remove conditional, and of two changes that agree for every size only the first is made (boundary's,
then comparison's, then other comparison's).

Only numbers have an order: `==` on two `boolean`s or references, and `== null`, get no mutant
here. A comparison of `float`s or `double`s gets only changes that treat `NaN` as Java does, so `x
< y` gets none (`x != y` would differ for `NaN` too). A change that differs only for a negative
size or length, `items.size() == 0` to `items.size() <= 0`, is skipped as equivalent.

It's in `stronger` because, measured on mutastic's own code, most of what it missed was noise: a
loop counter that counts up to its end (`i < n` and `i != n` stop at the same place), and a size
compared with a value it never passes.

```java
if (total >= 100)   // becomes: if (total == 100)
```

## Other comparison

`mutastic/other-comparison`, in the `stronger` set. A comparison becomes each of the others, and
any condition its opposite: `<` becomes `>`, `>=` or `==`; `==` becomes `!=`, `<` or `>`; `==
null` becomes `!= null`; `if (order.isPaid())` becomes `if (!order.isPaid())`. It goes unnoticed
when no test checks what happens on one side of an `if`.

A test that catches the mutants of [boundary](#boundary), [comparison](#comparison) and [remove
conditional](#remove-conditional) catches these too, so in the defaults their catches would only
add to the score. It replaced `mutastic/negate-conditional`, whose change is the condition's
opposite.

```java
if (order.isPaid())   // becomes: if (!order.isPaid())
if (coupon == null)   // becomes: if (coupon != null)
```

## Remove conditional

`mutastic/remove-conditional`. A condition stops deciding: the code it guards always runs, or never
does. Each condition gets two mutants, one each way. It goes unnoticed when no test needs the
condition to be true one time and false another.

```java
if (order.isPaid())   // becomes: if (true), and: if (false)
```

## Logical connector

`mutastic/logical-connector`. In a condition of two tests, `&&` becomes `||` and `||` becomes
`&&`. The two give different answers exactly when one test holds and the other doesn't, so it goes
unnoticed when no test has one of them true and the other false. The card names both: "no test
checks `canShip()` with one of `order.isPaid()` and `order.inStock()` true and the other false".

```java
if (order.isPaid() && order.inStock())   // becomes: if (order.isPaid() || order.inStock())
```

The bytecode has no `&&` or `||`, only two tests that jump, so mutastic recognises the way javac
lays out a condition of two tests (in an `if`, a loop, a `return`, through a `!`) and turns the
first test's jump round. It leaves alone a condition of three or more tests, an `if` nested in
another on a line of its own (it compiles the same as `&&`), and a test that reads what the one
before it binds, `value instanceof Integer number && number > 0`, which `||` couldn't run. When the
statement has more than one `&&` or `||` the card can't say which, and says so.

## Math

`mutastic/math`. `+` becomes `-`, `*` becomes `/`, and back, on `int` and `long`. It goes
unnoticed when tests only use values where the two give the same answer, such as adding `0` or
multiplying by `1`.

```java
return price * quantity;   // becomes: return price / quantity;
```

## Arithmetic replacement

`mutastic/arithmetic-replacement`, in the `stronger` set. `+` becomes `*`, on `int` and `long`. It
goes unnoticed when tests only add numbers whose sum and product agree, `2 + 2` say.

```java
return price + shipping;   // becomes: return price * shipping;
```

## Return value

`mutastic/return-value`. A method returns the value its kind of method most plausibly gets wrong,
instead of what it computed. It goes unnoticed when tests call the method but never look at what it
returns.

| The method returns | The mutant returns |
|---|---|
| `boolean` | the other one: `true` becomes `false`, `false` becomes `true`, and a computed one becomes each |
| a number | `0`, or `1` where it returns `0` |
| `Optional` | `Optional.empty()` |
| `String` | `""` |
| `List`, `Collection` or `Iterable` | `List.of()` |
| `Set`, `Map` | `Set.of()`, `Map.of()` |
| `Stream` | `Stream.empty()` |
| `Boolean`, `Integer`, `Long` and the other boxed numbers | as their primitive does |
| anything else | `null` |

```java
return subtotal + shipping;      // becomes: return 0;
return customer.isEligible();    // becomes: return false; and: return true;
return "Order " + id;            // becomes: return "";
return orders.stream().filter(Order::isPaid).toList();   // becomes: return List.of();
```

A return that already gives that value, `return List.of();` say, can't be changed by it, and is
[skipped as equivalent](/concepts/equivalence/).

## Remove void call

`mutastic/remove-void-call`. A call that returns nothing is removed. It goes unnoticed when no test
checks what the call does.

```java
inventory.reserve(item);   // becomes: nothing, the line is gone
```

## Remove discarded call

`mutastic/remove-discarded-call`. A call whose result is thrown away is removed: `items.add(item);`,
`seen.put(key, value);`. Its result isn't used, so only what it does matters. It goes unnoticed
when no test checks what the call does.

```java
order.lines().add(line);   // becomes: nothing, the line is gone
text.append(", ");         // so does this, though append returns the builder
```

`Objects.requireNonNull(x);`, which only checks a value isn't `null`, is skipped as arid.

Constructors are left alone: removing one would leave an object half made, not a gap in the tests.

## Remove assignment

`mutastic/remove-assignment`. An assignment to a variable that already has a value is removed, so
the variable keeps that value. What it would have been given is still worked out, so a call on the
right-hand side still runs. It goes unnoticed when no test checks anything that depends on the new
value.

```java
total = total + line.price();   // becomes: total stays as it was
retries = 0;                    // becomes: retries stays as it was
```

A variable's first value is left alone, as the code wouldn't run without it. So is code compiled
without its table of local variables (`-g:none`, or no `vars` in `-g`), which doesn't say what's a
variable. An assignment whose value nothing reads, because the variable is assigned again first or
never used, is skipped as equivalent. `i++` isn't an assignment here.

## Remove field write

`mutastic/remove-field-write`. A write to a field is removed, so the field keeps the value it had.
It's in the `stronger` set. It goes unnoticed when no test checks the field afterwards, directly or
through what reads it.

```java
this.status = Status.PAID;   // becomes: status stays as it was
```

Constructors and static initialisers are left alone, as they are for every operator, and a setter
with nothing else in it is skipped as arid. A write of a default value, `count = 0;` in a `reset()`,
is kept: that's what `reset()` is for.

## Stream stage removal

`stream/remove-stage`. A stage of a stream pipeline is removed, and the stream goes on without it:
`filter`, `distinct`, `sorted`, `limit`, `skip`, `dropWhile` or `takeWhile`, on `Stream`,
`IntStream`, `LongStream` and `DoubleStream`. It goes unnoticed when no test has input the stage
would change.

```java
orders.stream().filter(Order::isPaid).count()   // becomes: orders.stream().count()
```

Removing `sorted()` before a result that ignores order (`count()`, `anyMatch`, `min`, `sum` and
the like) can't change anything, so it's skipped as equivalent; so is removing `distinct()` before
a result that ignores duplicates.

## Stream match swap

`stream/swap-match`. `anyMatch`, `allMatch` and `noneMatch` swap places: `anyMatch` becomes
`allMatch` and `noneMatch`, and each of the others becomes `anyMatch`. It goes unnoticed when no
test has input where some elements match and some don't.

```java
items.stream().anyMatch(Item::isFragile)   // becomes: .allMatch(…), and: .noneMatch(…)
```

## String method swap

`library/swap-string`. A `String` method becomes the similar one: `startsWith` and `endsWith`,
`toUpperCase` and `toLowerCase`, `stripLeading` and `stripTrailing`. It's in the `stronger` set. It
goes unnoticed when no test
has text where the two differ.

```java
if (name.endsWith(".csv")) {   // becomes: name.startsWith(".csv")
```

## indexOf swap

`library/swap-index-of`. `String.indexOf` and `lastIndexOf` swap places. It's in the `stronger` set.
It goes unnoticed when no test has text with what's searched for in it twice.

```java
int dot = name.lastIndexOf('.');   // becomes: name.indexOf('.')
```

A search whose result is only tested for being there, `name.indexOf('.') >= 0`, is skipped as
equivalent, as both find it or neither does. A search with a starting point, `indexOf(x, from)`, is
left alone.

## Math method swap

`library/swap-math`. `Math.min` and `Math.max` swap places, and so do `Math.floor` and `Math.ceil`.
It's in the `stronger` set. It goes unnoticed when no test has values where the two differ.

```java
int size = Math.min(requested, limit);   // becomes: Math.max(requested, limit)
```

Rounding a whole number, `Math.floor((double) count)`, is skipped as equivalent, as it rounds to
itself either way.

## Choosing operators

A run uses the `defaults` set: every operator above but those in `stronger` and `extended`. To
choose, give a list of sets, operator ids and namespaces, any with a `-` in front to leave it out:

| Choice | Runs |
|---|---|
| `defaults` | What runs unless told otherwise |
| `stronger` | The defaults and the operators in `stronger` |
| `extended` | The operators on modern APIs alone: add it to another set |
| `defaults,extended` | The defaults and the operators in `extended` |
| `all` | Every operator, in every set |
| `mutastic/arithmetic-replacement` | That one operator |
| `stream` | Every operator in that namespace: `stream/remove-stage`, `stream/swap-match` |
| `-stream` | The defaults without the stream operators |
| `defaults,mutastic/arithmetic-replacement` | The defaults and that one |

On the command line, or from a build plugin, as [`--operators`](/reference/run/#operators):

```sh
mutastic run --operators=stronger
mutastic run --operators=defaults,-stream/swap-match
```

Or for every run, in `mutastic.yaml`, which a command-line choice replaces:

```yaml
operators:
  - stronger
  - -stream/swap-match
```

A run of one mutant, by id (`verify`, `explain`, `run --only`), looks among every operator, so a
mutant any run found can always be checked again.

A mutant's id doesn't depend on which operators run: choosing more adds mutants, and never changes
the ids of the others.

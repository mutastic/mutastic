Your tests pass and cover every line: does that mean they check what the code does? This runs
mutastic on `samples/pricing`, a small Gradle project in mutastic's repository whose tests pass and
cover every line, and still miss something. Then it closes the gap and proves it. It needs the
[command line](/getting-started/install/) on your `PATH`.

## 1. Run it

```sh
git clone https://github.com/mutastic/mutastic.git
cd mutastic
mutastic run samples/pricing
```

mutastic reads the build, runs the tests once to see what each line is reached by, then changes
the code one small way at a time and runs the tests that reach each change. One change gets past
them:

## 2. Read it

- **The gap**, first: no test calls `discount()` with exactly 100, so nothing tells `>=` from `>`.
- **The change** that got through, on its line.
- **The evidence**: the values your tests actually passed (50 and 250), and the tests that reach
  the line, which all still pass with the change in.
- **A test that would catch it**, with what the code returns today (10) and with the change (0).
  Today's value is what the code does, not necessarily what it should: check it's what you mean.
- **The commands** to prove a fix, to see the mutant again, or to record a decision not to test it.
  Each names this project, so it works as it's copied. `m855c8e3c` is the mutant's id.

The summary says how the rest went. The score is high enough to pass, but the run still shows the
one it missed: a passing score isn't a reason to leave a gap you can close.

## 3. Close the gap

The card's test asserts what `discount(100)` gives today, 10. Is that right? The method's comment
says 10% off orders of 100 or more, so yes. Add the test to
`samples/pricing/src/test/java/com/example/pricing/PricingTest.java`:

{/* added to: samples/pricing/src/test/java/com/example/pricing/PricingTest.java */}
```java
@Test
void discountAtTheTotalEdge() {
  assertEquals(10, new Pricing().discount(100));
}
```

With `>` in place of `>=`, `discount(100)` is 0, and this test fails. When today's value isn't the
one the code should give, keep the test and write the right value: then it's the code that needs
fixing. See [Suggested tests](/concepts/suggested-tests/).

## 4. Prove it

Run the command the card offered as "done when":

```sh
mutastic verify m855c8e3c samples/pricing
```

<Code code={verify} lang="ansi" />

The mutant is caught: a test now fails when `>=` becomes `>`. `verify` exits with 0 when every
mutant it names is caught, and 1 while one is still missed, so a script or a coding agent can use it
as the check that a gap is closed.

## 5. Run it again

```sh
mutastic run samples/pricing
```

<Code code={runAgain} lang="ansi" />

Every mutant is caught, and the score says how far it moved since the last run.

Your report command fetches the day's sales on a worker thread, waits for it, builds the text,
logs how long it all took, records that time for a dashboard, and prints the report. A mutastic
run skips some of that as [arid](/concepts/arid/) and counts the rest, and the line between them
isn't always where you'd draw it. This guide takes one such class through a run: which mutants are skipped and why, which
are counted, how to check the skips, and how to bring back the one your tests rely on.

## The class

`samples/sales` in mutastic's repository:

{/* from: samples/sales/src/main/java/com/example/sales/Summary.java */}
```java
  /** What the report command prints. */
  public static void print(Supplier<List<Long>> sales, Metrics metrics)
      throws InterruptedException {
    System.out.println(of(sales, metrics));
  }

  public static String of(Supplier<List<Long>> sales, Metrics metrics) throws InterruptedException {
    long start = System.nanoTime();
    var fetched = new AtomicReference<List<Long>>(List.of());
    var worker = new Thread(() -> fetched.set(sales.get()));
    worker.start();
    worker.join(5_000);
    List<Long> amounts = fetched.get();
    var text = new StringBuilder(amounts.size() * 8);
    long total = 0;
    for (long amount : amounts) {
      text.append(amount).append('\n');
      total += amount;
    }
    text.append("total ").append(total);
    long took = (System.nanoTime() - start) / 1_000_000;
    log.info("summed {} amounts in {} ms", amounts.size(), took);
    metrics.record("summary.ms", took);
    return text.toString();
  }
```

Its one test checks what the command prints, from a source that takes a moment, as a real one
does:

{/* from: samples/sales/src/test/java/com/example/sales/SummaryTest.java */}
```java
  @Test
  void printsEachAmountThenTheTotal() throws Exception {
    var printed = new ByteArrayOutputStream();
    var console = System.out;
    System.setOut(new PrintStream(printed, true, StandardCharsets.UTF_8));
    try {
      Summary.print(slowly(List.of(12L, 30L)), (name, value) -> {});
    } finally {
      System.setOut(console);
    }
    assertEquals(
        "12\n30\ntotal 42" + System.lineSeparator(), printed.toString(StandardCharsets.UTF_8));
  }
```

## The run

```sh
mutastic run samples/sales
```

<Code code={run} lang="ansi" />

The test catches most of it: a removed `start()` or `join`, a removed `append`, the total's `+`.
Some mutants are skipped as arid, and the time worked out at the end is missed. Here is each, in
turn.

## A log line

Removing the `log.info` call is skipped as `arid: only writes output`, by the
[`output`](/reference/arid/#output) rule. The report comes out the same without it, and a test
that read the log line would break the next time someone reworded it. Keep this skip unless the log
is the product, an audit log say, and a test reads it.

## Its format string

With `--operators=stronger`, strings get mutants too. The format string,
`"summed {} amounts in {} ms"`, only goes into the log call, so it's skipped by the same rule:

```sh
mutastic explain ma5436468 samples/sales
```

<Code code={formatString} lang="ansi" />

The values after it don't change that: the string still goes nowhere but the log. Nor would a
value worked out only for the log, `(System.nanoTime() - start) / 1_000_000` passed straight to
`log.info`, or through a local nothing else reads: its mutants would be skipped as
`arid: only feeds a log line`, by the same rule.

## A value logged and recorded

Here the time goes somewhere else too:

```java
    long took = (System.nanoTime() - start) / 1_000_000;
    log.info("summed {} amounts in {} ms", amounts.size(), took);
    metrics.record("summary.ms", took);
```

So the `-` becoming `+` and the `/` becoming `*` are counted, and missed, and so is removing
`metrics.record`: the value reaches more than the log, and a dashboard reads the metric. mutastic
skips a value only when every use of it, on every path, is a log call's or a print's argument.

If a test should check the metric, write it: a `Metrics` that keeps what it's given, and an
assertion on it. If nobody tests the timing, because it's checked in the dashboards, say so
yourself. `mutastic ignore` records the decision, with its reason, in `.mutastic/ignores.yaml`, for
review with the code:

```sh
mutastic ignore m3b95337d samples/sales --as=telemetry --reason="timing only, checked in dashboards"
```

<Code code={ignored} lang="ansi" />

Do the same for the others. `--as=telemetry` counts them apart in the summary, and each ignore
lapses when its line changes, so a value later used for more is counted again.

## A buffer's size

`amounts.size() * 8` sizes the `StringBuilder`, and its `*` becoming `/` is skipped as
`arid: only sizes a collection's first allocation`, by the
[`capacity`](/reference/arid/#capacity) rule. A builder grows as it needs to, so the text is the
same either way. Keep it.

## Waits

Removing `worker.join(5_000)` isn't arid, though it has a time limit: without it, `of` reads the
sales before the worker has fetched them, a race, and the test catches it. The
[`waits`](/reference/arid/#waits) rule skips only a removed `Thread.sleep` or `TimeUnit.sleep`,
which changes when the code gets somewhere, not what it finds there.

The limit itself, `5_000`, counts too: a shorter one gives up on the worker sooner, and `of` reads
the sales unfinished. Only how long a sleep waits is arid, by the
[`wait-times`](/reference/arid/#wait-times) rule.

## The command's output

Removing `System.out.println(...)` in `print` is skipped as `arid: only writes output` too, by the
same rule as the log line. Here, though, the output is the product: it's what the report command is
for, and the test reads it.

```sh
mutastic explain m03c37b45 samples/sales
```

<Code code={explained} lang="ansi" />

The audit runs every arid mutant anyway, to show which skips your tests would catch:

```sh
MUTASTIC_ARID=audit mutastic run samples/sales
```

<Code code={audit} lang="ansi" />

One of them was caught by an assertion, in `Summary.print()`: a test checks what that code does, so
the skip is hiding a contract. The audit says how: bring the rule back there, for that method and that rule only,
with a reason, in `mutastic.yaml`:

{/* added to: samples/sales/mutastic.yaml */}
```yaml
rules:
  - mutate: com.example.sales.Summary#print
    arid: [mutastic:output]
    reason: the report is what the command prints, and scripts read it
```

The run after it runs the `println`'s mutant, and the test catches it. The log line and the buffer
stay skipped, and the three ignored mutants are counted apart:

<Code code={kept} lang="ansi" />

## What you end with

- Skips that are right for this code, kept: the log line and its text, the buffer's size.
- A timing the log and a dashboard use, which no test checks, ignored with a reason, by sort.
- The one skip that hid a contract, the command's output, brought back for one method and one rule,
  with the test that catches it.

Each rule, what it can hide and the setting that brings it back are in
[Arid rules](/reference/arid/).
